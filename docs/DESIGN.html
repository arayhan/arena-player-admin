Design System — Arena Player Admin

Reference artifact. Not production code, not a client deliverable. Tokens are normative in docs/DESIGN.md; if this page and that file disagree, that file wins.

The admin's language, in one line: same palette as the public site, none of its motion. Dense, boring, fast. The admin is doing data entry under time pressure with a customer waiting on WhatsApp — delight is a tax here. Every omission on this page (no Orbitron, no scroll effects, no hero, no fluid type) is that sentence being applied.

Ink needs 4.5. Borders need 3.0 on both sides. All twelve figures clear.

These borders are a correction, not a preference. The web palette's -300 tier measured 1.29–1.90 against both the page and its own fill — three to four times under the 3:1 the rule demands. Those borders were decorative while being documented as one third of a state signal, which is worse than having no border: the document claimed a guarantee the pixels did not deliver. Web's own component tokens name no borderColor at all, so the rule had never been tested against a measured value. Worth telling the web repo — if its Phase 2 slot cells grow a state-carrying border, they will fail the same way.

02The layering rule, demonstrated

Primitive → semantic → component, three hops, no shortcuts. A component rule reaching a raw hex is a defect — the other repo's finish review caught seventeen of them as a single P0, on the very page that taught the rule.

Layer 1  --amber-700: #B45309;                      /* primitive: a hue */
Layer 2  --pending-line: var(--amber-700);          /* semantic: what it MEANS */
Layer 3  .ds-status--pending { border-color: var(--pending-line); }   /* component */

Every Layer 3 rule in this document's stylesheet reads a Layer 2 token. The one deliberate exception is page chrome — headings, the wrapper, this note — which is not part of the system and is marked as such in the CSS.

The row-divider exemption. grey-200 measures 1.24 on white. It separates rows; it carries no state and no information. WCAG 1.4.11 governs boundaries that are the signal, and a table rule is not one. Recorded so it does not read as the same oversight as the -300 tier.

03Controls

The fourth is aria-disabled, not disabled — a natively disabled button drops out of the tab order mid-interaction and moves focus somewhere the admin did not choose. It has its own visual rule: the other repo shipped an aria-disabled state that was byte-identical to idle, directly beneath a paragraph explaining why aria-disabled was correct.

Kata sandi salah.

Error text ties to its field via aria-describedby, and focus moves here on failure rather than staying on a dead button. Baseline, not a nicety — the admin works this app from the keyboard.

06Payment proof, and its expiry

A presigned GET, 120 seconds. Not fifteen minutes: it is a bearer capability for a document carrying a name, an amount, and a bank transfer, and it leaks through browser history and the Referer header.

bukti transfer
(specimen — no real proof exists yet)
presigned GET · expires in 120s

An expiring URL on a page left open renders a broken image. The <img> carries an onError that swaps in the recovery button above — the only client component in v1. Everything else on every screen is a Server Component.

Never next/image on a proof. The optimizer proxies the presigned URL, writes the decoded output to an on-disk cache keyed by URL, and serves it from a stable /_next/image?url=… path with a long TTL — copying a private payment document out of the private bucket and outliving the presign entirely. Plain <img>. This is the worst mistake available in this repo, and it looks like an improvement.

The 409 is not an error state, it is the normal case. The admin's screen is stale by default — two tabs, a phone and a laptop, and an expiry job all write the same rows. Every mutation carries a where status in (…) guard and zero rows means somebody else got there first.

The 503 is scoped, never global. A missing Phase 4 table degrades this app to its core function; it does not brick it. Someone will otherwise wrap the root layout in the schema guard because it looks tidier, and the first missing migration takes the bookings console down with it.

The mutation returned zero rows. That is not an error to swallow — the expiry job flipped this booking between page render and click. Respond 409, re-render, and let the admin see what actually happened.

Why there is no "un-expire" button here. Confirming an expired row can collide with uniq_active_slot and raise 23505: another booking may have taken the slot after it was released. 09What is deliberately not on this page

AbsentWhy
Orbitron, the fluid clamp() scale, section transitions, any hero Landing-page art direction. A data table does not want it
Any motion beyond 160ms colour transitions No GSAP in this repo, so no src/lib/motion.ts either. Reduced-motion still removes even those
Any price No rate card is confirmed. Web's rule forked at its 2026-08-11 checkpoint — /booking now renders one, / still doesn't — so this is no longer "the same rule as the public site," just the same missing figure both apps are waiting on
A loading skeleton Server Components with no client fetching. The page arrives rendered or it does not arrive
Slot-blocking UI Phase 4, and it is behind 4-gate-blocks.md — a block web does not read is a silent no-op
Real data of any kind The bookings table does not exist in Neon yet. Every value here is invented and labelled as a specimen

This page is not under check:domain, and must not be added to it. That check covers src/domain/*.ts only. Token drift between the repos is cosmetic; slot-string drift silently disables anti-double-booking in both apps. Putting a documentation file under a byte diff would train people to skim past that check's failures — the one check in this project that must never be skimmed past.
